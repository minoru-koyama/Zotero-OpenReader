## Deepgram verified live on 1.16.16-beta8, and how the bridge was reached (2026-11-02 08:05)

The Deepgram case (`test/zotero-dev/cases/deepgram.md`) ran to empty in the
isolated profile against the beta8 build, all eight items PASS. The key
was typed by the owner directly into the pane's Deepgram field and stays
in that profile; only its length (40) was ever read.

- **Reaching the bridge from a harness with no MCP tools.** This session
  exposes no `mcp__zotero-dev__*` tools, so `@introfini/mcp-server-zotero-dev`
  1.1.4 was installed under `.tmp/zotero-dev/mcp` and driven by a small
  stdio JSON-RPC client (`call.mjs` for one tool, `exec.mjs` for a script
  file). The isolated instance ran as a managed service with the wizard's
  own arguments (`MOZ_NO_REMOTE=1 … -no-remote -profile … -datadir …`);
  a backgrounded `&` launch did not survive its shell, the supervised
  service did. The bridge listens on **6101** in that profile
  (`user.js`: `extensions.mcp-rdp.port`), not 6100.
- **Voices.** `Connected. 41 voices available. Synthesis works.` — 41
  English Aura-2 voices, the public filter's own count, filed
  `en-US (36)`, `en-GB (2)`, `en-AU (2)`, `en-PH (1)`; ids are
  `deepgram::aura-2-…-en` and the document voice record confirms the
  shape (`{"voice":{"id":"deepgram::aura-2-thalia-en","lang":"en"}}`).
- **Enable does not change the line.** Test connection writes
  `Connected…`; the Enable after it leaves the text alone and shows itself
  in `deepgram.enabled` and the field's lock. Read those, not the line.
- **The catalog loads when a session prepares.** A freshly opened reader
  has `_allVoices` 0; `toggleReadAloudPopup(true)` loads 41 voices and 4
  languages, tier `deepgram`. A `selectVoice` before that is silent.
- **Playback needs a trusted gesture.** A script-started session meets the
  autoplay gate (`NotAllowedError`, `AudioContext was prevented…`). A
  trusted `Shift+Space` through `nsITextInputProcessor` on the main window
  **with the reader's tab selected** is consumed and starts it; with the
  library tab selected the same key is consumed by something else and the
  session does not move. Playing then reads `audio.state: "running"`,
  gain 0, `playbackTime` 1.013 → 2.508 s, `currentIndex` 8 → 9 → 10, no
  error, prefetch `{sentences: 3, requests: 1, order: [8,9,10]}`.
- **`(cached)` is not reachable this way.** Eleven adapter lines
  `deepgram: no word timestamps for N chars (audio from aura-2-thalia-en),
  highlighting the sentence` — one per segment. Replaying a sentence still
  in the Engine's clip store wrote **no line at all** and resumed in under
  a second: the clip store answers before `remote-interface`, whose memory
  cache is what prints `(cached)`. The case's expectation was corrected.
- **Word mode draws the sentence.** With `highlight.word` true and
  Zotero's level `word`, `highlight()` reports `granularity: "sentence"`,
  `activeWordTimestamp: "stand-in"`, `segment: true`, identical across
  three samples while the index advanced — no word-by-word progression.
- **Restoring a cleared pref needs the value first.** Clearing
  `readAloud.volume`, `prefetchSentences`/`Requests` and `deepgram.enabled`
  alone was rewritten by the plugin's own observers; setting the baseline
  value, waiting, then clearing the user flag held. Final state: volume
  100, prefetch 5/2/custom true, `highlight.word` true,
  `deepgram.enabled` false, `readAloud.defaultVoice` empty — every one with
  no user value; positions 0, readers 0, the fixture item erased, key kept.
- **A wrong API signature looks like a broken build.** `Zotero.Items.getAll`
  with four arguments throws, and the bridge answers a bare `undefined`;
  check the signature and `zotero_read_errors` before suspecting the build.

The scripts that ran are in `test/zotero-dev/scripts/deepgram/`, with the
limits above in its README.
